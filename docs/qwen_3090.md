# 在 Jupyter 服务器的 3090 上运行本地 Qwen

这套配置适合实验阶段频繁调用模型：一次下载模型和占用 GPU 后，不按 API token 计费。默认模型是 `Qwen/Qwen2.5-7B-Instruct`，FP16 权重约占 14 GB；脚本为 24 GB RTX 3090 保留 KV cache 和运行余量。它不通过 SSH，也不会自动暴露公网端口。

## 1. 在 Jupyter 的 Terminal 中拉取并安装

```bash
cd /你的/iAgent_reproduction
git pull
bash scripts/setup_qwen_vllm_3090.sh
```

若服务器的 Conda 命令尚未初始化，先按管理员提供的方式 `source` 对应的 `conda.sh`，再运行脚本。首次安装会下载 Python 包；首次启动还会从 Hugging Face 下载模型，需要服务器具备相应网络或镜像访问权限。

## 2. 启动模型服务

在第一个 Terminal：

```bash
cd /你的/iAgent_reproduction
conda activate iagent-qwen-cu121
export IAGENT_API_KEY='换成仅自己知道的随机字符串'
GUIDED_DECODING_BACKEND=lm-format-enforcer bash scripts/start_qwen_vllm_3090.sh
```

保持该 Terminal 运行。脚本默认监听 `127.0.0.1:8000`，因此同一台服务器上的实验可访问，其他机器不能访问。模型完全启动后，另开一个 Jupyter Terminal：

```bash
cd /你的/iAgent_reproduction
conda activate iagent-qwen-cu121
export IAGENT_API_KEY='与启动服务时相同的字符串'
export IAGENT_OPENAI_BASE_URL='http://127.0.0.1:8000/v1'
bash scripts/check_qwen_vllm.sh
```

`check_qwen_vllm.sh` 输出模型列表即代表服务可用。

### CUDA 驱动兼容性

脚本固定安装 vLLM `0.6.3.post1` 的 CUDA 12.1 wheel，适合 `nvidia-smi` 显示 CUDA 12.2 的服务器驱动。不要在这个环境中执行不带版本限制的 `pip install -U vllm`：它可能升级 PyTorch CUDA runtime，进而报 `The NVIDIA driver on your system is too old`。若服务器管理员升级了驱动，可另建新环境后再评估更新 vLLM。

脚本也固定 `transformers==4.45.2`，避免 pip 安装过新的 Transformers 后与该 vLLM 版本的 tokenizer 接口不匹配。

该 vLLM 版本默认的 `outlines` guided-decoding 后端会依赖一个已失效的 `pyairports` 包。启动脚本因此改用 vLLM 官方支持的 `lm-format-enforcer` 后端，并显式安装该依赖；同时固定 NumPy 1.26.4，因为 vLLM 0.6.3 不支持 NumPy 2。

## 3. 运行 iAgent

先用一个用户验证调用链路，再扩大样本：

```bash
python -m iagent_reproduction.run_instructrec \
  --domain books --agent iagent --backend qwen \
  --model Qwen/Qwen2.5-7B-Instruct --users 1

python -m iagent_reproduction.run_instructrec \
  --domain books --agent i2agent --backend qwen \
  --model Qwen/Qwen2.5-7B-Instruct --users 1
```

`i²Agent` 会对一名用户的历史逐条生成 profile，LLM 调用数显著更多；先小样本跑通并记录耗时，再增大 `--users`。不要把 `IAGENT_API_KEY` 写进 notebook、脚本或 Git。

## 可调参数

如果出现 CUDA out-of-memory，按顺序减小上下文长度和并发：

```bash
MAX_MODEL_LEN=4096 MAX_NUM_SEQS=2 bash scripts/start_qwen_vllm_3090.sh
```

若确认该机器仅有你使用，可把 `GPU_MEMORY_UTILIZATION` 提到 `0.90`；不建议一开始使用更大的模型。若模型下载需要镜像，按你们服务器既有的 Hugging Face 镜像规范设置 `HF_ENDPOINT` 后再启动。

默认的 8192 上下文长度在该驱动与 vLLM 组合下最稳定。若单条 rerank 输入过长，优先通过 runner 的 `--max-static-chars` 和 `--max-candidate-chars` 控制输入，而不是盲目提高 `MAX_MODEL_LEN`；这两个值会打印在实验输出中，必须写入实验记录。

## A40（CUDA 12.4）

A40 的 46 GB 显存适合用较新的 CUDA 12.4 vLLM，并用 32K 上下文测试完整文本输入：

```bash
source /home/hqy/miniconda3/etc/profile.d/conda.sh
bash scripts/setup_qwen_vllm_a40.sh
conda activate iagent-qwen-a40
export IAGENT_API_KEY='choose-a-local-secret'
CUDA_VISIBLE_DEVICES=1 MAX_MODEL_LEN=32768 MAX_NUM_SEQS=1 GPU_MEMORY_UTILIZATION=0.85 \
  bash scripts/start_qwen_vllm_3090.sh
```

GPU 1 must still be checked with `nvidia-smi` immediately before launch. The name of the start script is retained for compatibility; it is a generic single-GPU vLLM launcher.

The A40 environment pins `transformers==4.51.3`, which meets vLLM 0.8.5's requirement while avoiding newer Transformers 5.x tokenizer API changes. Leave `GUIDED_DECODING_BACKEND` unset on A40 so vLLM can use its V1 engine; the older 3090 environment should explicitly use `lm-format-enforcer`.
